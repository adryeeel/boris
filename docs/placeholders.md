# Template values and variable names

Use this guide with the [setup checklist](setup.md) when configuring a copy of `template/`. Paths below refer to the copied workspace; links point to Boris's source files. Establish project-specific values with the user and do not invent a production domain, credentials or product claims.

## Replace project identity values

| Value in the template                  | Where and why                                                                                         | What to do                                                                                                                                                              |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project-template`                     | The root `package.json` name, local Compose project default and documentation identify the starter.   | Change the package name and Compose default to suitable project identifiers; update the README and relevant documentation.                                              |
| `@project-template/*`                  | Shared package names and references connect workspace dependencies, imports and configuration.        | Replace the scope consistently in package manifests, imports, lint grouping, TypeScript and other owned references. Preserve package suffixes. Regenerate the lockfile. |
| `Project Template` and its description | `apps/web/src/const/site.ts` supplies home-page copy and metadata; `README.md` has the starter title. | Replace with the agreed project title and description; update the README for the new project.                                                                           |
| `http://localhost:3000` and `en`       | Site constants supply the metadata base URL and document language.                                    | Set the agreed language and an actual HTTP(S) origin; keep localhost until a production origin is known.                                                                |

[Setup](setup.md) lists the files to search, commands and verification steps. The app package name `web` is a working identifier used in filters and Docker paths: keep it unless the task explicitly changes it and updates all its consumers. Preserve the license and its copyright notice.

## Configure values; keep the names

Uppercase environment variables and GitHub Actions settings are interfaces used by scripts and workflows. Their names are not project-name placeholders. Supply values where needed; do not rename them unless all producers, consumers and guidance are intentionally changed together.

| Name                                                 | Where and why                                                                                                                                                   | What to do                                                                                                                                                  |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `COMPOSE_PROJECT_NAME`                               | The local [Compose file](../template/compose.yml) accepts this standard Docker Compose override to separate local instances.                                    | Usually leave unset; set a distinct value when running parallel instances. The `project-template` fallback is the value to customize.                       |
| `PORT`                                               | Local and production Compose files use it for the loopback host port.                                                                                           | Leave unset for port 3000 or configure a free port. This is not the app's internal port.                                                                    |
| `DEPLOY_ENABLED`, `DEPLOY_PATH`, `DEPLOY_PROJECT`    | The [CD workflow](../template/.github/workflows/cd.yml) uses these GitHub variables to opt in and identify the server directory and production Compose project. | Configure their values only for an authorized deployment. Keep CD disabled until the target is ready.                                                       |
| `IMAGE_REF`                                          | The production Compose file consumes the exact image reference; CD supplies it from the published commit SHA.                                                   | Let CD set it; provide a previously published image reference for an authorized manual rollback.                                                            |
| `VPS_SSH_*`, `GHCR_READ_USERNAME`, `GHCR_READ_TOKEN` | CD reads these GitHub variables and secrets for the target host and registry.                                                                                   | Configure values in GitHub when deployment is authorized; never commit credentials. See [CD and secrets](../template/docs/delivery/cd.md) for each setting. |
| `PROJECT_ROOT`                                       | The [benchmark script](../template/agents/skills/perf/scripts/bench.sh) accepts an optional alternate checkout.                                                 | Usually leave unset; set a path only when benchmarking another checkout.                                                                                    |

GitHub-provided names such as `GITHUB_TOKEN`, `GITHUB_REPOSITORY` and `GITHUB_OUTPUT` are platform contracts. Do not replace them with project names. `DEPLOY_PROJECT` and `COMPOSE_PROJECT_NAME` identify Compose deployments; they do not rename npm packages or the app itself.

If the agent works only in the copied repository, provide this Boris guide and the setup checklist as task context or links. They intentionally live outside `template/` and are not automatically copied into the new application.
